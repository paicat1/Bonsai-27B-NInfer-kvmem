## 三、Design C 裁决：**保留为兜底防御——S3 不能替代它**

**四条依据**：

1. **病不同**。S3 治"未设 budget → 思考占满输出 → 空正文"（客户端逐请求设 budget 的通道）；Design C 治"**已设 budget，模型仍在思考区自行吐 EOS**"——budget 限长，**挡不住模型自己提前吐 EOS**；EOS 一到即走 stop 分支（`output_session.cpp` L553），S3 对该分支零影响。
2. **上游代码证实**：`output_session.cpp` 两 tag 间一字未动——"终止优先 → 空正文"行为原样保留。
3. **上游单测仍钉死旧契约**：`test_frontend.cpp` 上游未动（"terminal token at the thinking boundary did not take priority"断言原样）⇒ 上游明确不打算改此行为——纯 20261008 上该空正文场景**会继续发生且被视为正确**。
4. **场景真实非理论**：自建线即因实跑空收尾才做 Design C（后 78 请求实测无空收尾）。频率未知但非零。

**成本收益**：保留成本 = 12 行、原位重放（行号未变）、单测验收流程现成；收益 = 与 S3 合并后**完整覆盖空正文两条路径**（无 budget 的思考占满 + 有 budget 的 EOS 打断）。
**长期动作**：Design C 列为**上游回馈候选**（附我方单测改法，先例 = `ca4196ac` 与上游 context_store 自修）；若上游采纳，兜底转正、我方补丁面再减一处。
